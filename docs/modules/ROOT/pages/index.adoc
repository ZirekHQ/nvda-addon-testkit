= nvda-addon-testkit

End-to-end testing for NVDA add-ons, against a real NVDA, in CI.

Your add-on's logic can be unit-tested with stubs. What cannot be stubbed is whether it installs,
registers, and behaves inside NVDA itself. This kit provisions a disposable portable NVDA,
installs your add-on into it, and lets pytest drive it.

[source,python]
----
def test_my_addon_announces_itself(nvda, addon_under_test, assert_no_unexpected_errors):
    before = nvda.speech.index()
    nvda.keys.press("NVDA+shift+m")
    assert "my add-on is ready" in nvda.speech.wait_for("ready", timeout=10, since=before).text
    assert_no_unexpected_errors(nvda)
----

See xref:example-project.adoc[] for this same pattern applied to a real, working add-on.

== Core concepts

[cols="1,3"]
|===
|Fixture |What it gives you

|`nvda`
|a connected client, reset between tests

|`addon_bundle`
|the path to your built `.nvda-addon`

|`addon_under_test`
|that bundle, installed and enabled, NVDA restarted
|===

== Requirements

Windows to run the tests. NVDA is downloaded automatically — you do not need one installed, and
nothing touches an NVDA you already have.

Tests run serially: only one NVDA can own a desktop session, so `pytest-xdist` with more than
one worker is refused rather than silently producing nonsense.
